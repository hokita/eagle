# E2E Tests for Basic Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Playwright e2e suite covering eagle's core flows (sign-in/out, correct/incorrect translation checking, Explain, report/next-sentence), running against the real Go API and real Next.js frontend with Firebase emulators and a stubbed Explainer, on every PR via GitHub Actions.

**Architecture:** Move the Go API's business logic out of `package main` into an importable `internal/app` package so both the production `api/main.go` and a new `api/cmd/e2eserver` binary (same wiring, stub `Explainer`) can share it. Firebase Auth + Firestore emulators back real HTTP/auth/DB behavior; Playwright drives a real Chromium browser through the real UI, including the Auth emulator's own fake Google consent screen (no real OAuth). Tests discover their sentence data dynamically from the API response rather than hardcoding it, and run with a single Playwright worker (serial), because the app's single-email auth model (`ALLOWED_EMAIL`) means all tests share one Firebase Auth identity, and per-uid Firestore state must not race across parallel tests.

**Tech Stack:** Playwright Test (`@playwright/test`), Firebase Emulator Suite (Auth + Firestore), Go 1.25, Next.js 15 (static export via `output: "export"`), existing `api/cmd/seed` for fixture loading.

## Global Constraints

- Go module: `github.com/hokita/eagle`, Go `1.25.0` (go.mod), CI pins `setup-go@v5` with `go-version: '1.23'` (toolchain auto-upgrades per go.mod — matches existing `ci.yml`).
- `fe/next.config.ts` has `output: "export"` — the frontend is a **static export**. `next start` does not work with this config. Serving for e2e must build (`next build`) then serve the static `fe/out` directory with a plain static file server.
- `NEXT_PUBLIC_*` env vars are inlined at `next build` time, not runtime — they must be set in the process environment *before* invoking `next build` for e2e.
- Backend `requireAuth` (in the code being moved to `internal/app/auth.go`) allows exactly **one** email via `ALLOWED_EMAIL` — not a list. All e2e tests must sign in with the same fixed test email.
- Existing emulator convention (from `api/firestore_repo_test.go`, already in the repo): project id `eagle-test`, `FIRESTORE_EMULATOR_HOST` env var auto-detected by `firestore.NewClient`, and a documents-wipe via `DELETE http://{host}/emulator/v1/projects/eagle-test/databases/(default)/documents`. Reuse this exact convention — do not invent a new one.
- `auth_firebase.go`'s doc comment already states it "Honors FIREBASE_AUTH_EMULATOR_HOST for local development" — no backend code change needed for Auth emulator support, only for the stub Explainer.
- `api/cmd/seed/main.go` already seeds NDJSON rows into the `sentences` Firestore collection via `firestore.NewClient(ctx, projectID)` — reuse it as-is for e2e fixtures; do not write a new seed script.

```go
package app

import "net/http"

// NewMux wires all HTTP routes with CORS and auth, matching the API's
// public surface exactly.
func NewMux(srv *Server, verifier TokenVerifier, allowedEmail, frontendURL string) *http.ServeMux {
	auth := func(h http.HandlerFunc) http.HandlerFunc {
		return withCORS(frontendURL, requireAuth(verifier, allowedEmail, h))
	}

	mux := http.NewServeMux()
	mux.HandleFunc("/api/sentence/random", auth(srv.getRandomSentence))
	mux.HandleFunc("/api/answer/check", auth(srv.checkAnswer))
	mux.HandleFunc("/api/answer/explain", auth(srv.explainAnswer))
	mux.HandleFunc("/api/sentence/report", auth(srv.reportSentence))
	mux.HandleFunc("/api/liveness", livenessHandler)
	return mux
}
```

## Task 4: Conditionally connect the frontend to the Auth emulator

**Files:**
- Modify: `fe/src/lib/firebase.ts`

**Interfaces:**
- Consumes: `NEXT_PUBLIC_FIREBASE_AUTH_EMULATOR_HOST` env var (set only for e2e builds, never in production).
- Produces: no change to exported `app`/`auth` names or types — same `export const auth: Auth`.

- [ ] **Step 1: Add the conditional emulator connection**

```ts
import { initializeApp } from 'firebase/app'
import { getAuth, connectAuthEmulator, type Auth } from 'firebase/auth'

const firebaseConfig = {
  apiKey: process.env.NEXT_PUBLIC_FIREBASE_API_KEY,
  authDomain: process.env.NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN,
  projectId: process.env.NEXT_PUBLIC_FIREBASE_PROJECT_ID,
}

export const app = initializeApp(firebaseConfig)

// getAuth() validates the API key (a real network-capable call, not just a
// format check) and must not run during Next.js's server-side prerender of
// this static-export app. Every real call site (onAuthStateChanged, signOut,
// signInWithPopup) only runs client-side, inside useEffect/event handlers,
// which never execute during prerendering — so this fallback is never
// actually invoked with a live `Auth` on the server.
export const auth: Auth = typeof window !== 'undefined' ? getAuth(app) : ({} as Auth)

const authEmulatorHost = process.env.NEXT_PUBLIC_FIREBASE_AUTH_EMULATOR_HOST
if (typeof window !== 'undefined' && authEmulatorHost) {
  connectAuthEmulator(auth, authEmulatorHost, { disableWarnings: true })
}
```

```ts
export const TEST_EMAIL = 'e2e-test@example.com'

  id: number
  japanese: string
  english: string

    page.waitForResponse(
      res => res.url().includes('/api/sentence/random') && res.request().method() === 'GET' && res.ok()
    ),

      await popup.getByLabel(/email/i).fill(TEST_EMAIL)
      await popup.getByRole('button', { name: /sign in/i }).click()
    })(),
  ])
  await expect(page.getByRole('heading', { name: 'Eagle' })).toBeVisible()
  return response.json()
```

## Task 12: GitHub Actions workflow

**Files:**

- [ ] **Step 1: Write the workflow**

```yaml
name: E2E

on:
  pull_request:

jobs:
  e2e:
    name: E2E
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version: '1.23'

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: npm
          cache-dependency-path: e2e/package-lock.json

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'

      - name: Install Firebase CLI
        run: npm install -g firebase-tools

      - name: Install e2e dependencies
        working-directory: e2e
        run: npm ci

      - name: Install Playwright browsers
        working-directory: e2e
        run: npx playwright install --with-deps chromium

      - name: Install frontend dependencies
        working-directory: fe
        run: npm ci

      - name: Run e2e suite
        working-directory: e2e
        run: npm run test:e2e

      - name: Upload Playwright report on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: e2e/playwright-report/
          retention-days: 7
```

Frontend dependencies are installed as a separate explicit step because `playwright.config.ts`'s `webServer` command (`npm run build`) needs `fe/node_modules` already present — it does not run `npm ci` itself.
