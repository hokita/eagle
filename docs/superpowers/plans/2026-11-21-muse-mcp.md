# Muse connection (MCP server) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve four MCP tools at `/mcp` on `eagle-api` so Muse can run eagle's translate-and-grade loop
for the owner, writing to the same Firestore history the app uses.

**Architecture:** The streamable HTTP MCP handler from the official Go SDK is mounted in the existing
`NewMux`, behind a bearer-token middleware ported from owlet. It uses a per-instance rate limiter and a
fixed owner uid. The tools call the same `Server` methods and repo as the REST handlers. The REST auth
is untouched.

**Tech Stack:** Go 1.27.4 toolchain (go directive stays 1.25.0), `github.com/modelcontextprotocol/go-sdk`
v1.8.0, Firestore, Cloud Run (asia-northeast1), GitHub Actions, Playwright e2e with Firebase emulators.

**Spec:** `docs/superpowers/specs/2026-11-21-muse-mcp-design.md`

## Review Focus

1. **A `sentence_id` that doesn't exist, or that is ≤ 0** (Muse makes ids up or reuses old ones).
   `check_answer` and `report_sentence` must return `Sentence <id> not found`, never `Internal error`,
   and must write nothing. Test: Task 4 `TestMCPCheckAnswerUnknownSentence`,
   `TestMCPReportUnknownSentence`.
2. **A huge mistake history.** `list_mistakes` must stay small: at most 50 sentences per call and 3
   wrong answers each, with `total` and `has_more` correct at the edges (offset = total, offset past
   the end). Test: Task 4 `TestMCPListMistakesPaging`.
3. **Japanese and multibyte answers.** The owner may answer in Japanese, or with curly quotes from a
   phone IME. The byte cap (2000, same as the app) must not split runes in error text. `’` must grade
   the same as `'`, and a Japanese answer is graded wrong and recorded as written. Test: Task 4
   `TestMCPCheckAnswerMultibyte`.
4. **Concurrent calls.** Muse may call tools in parallel. The limiter must be race-free and the owner
   uid must never come from the request. Test: Task 3 `TestRateLimiterConcurrent` (run with `-race`).
5. **Token rotation and misconfiguration.** The old token gets `401` right after a redeploy with a new
   secret version. A Firebase ID token sent to `/mcp` gets `401`, and the MCP token sent to `/api/*`
   gets `401`. With the token set but `MCP_OWNER_UID` missing, `/mcp` gets `401` (not a 500, and no
   writes under an empty uid). Tests: Task 5 `TestMuxMCPAuth`; post-deploy check in Task 8.

### Task 4: MCP tools

**Before Step 1:** ask the owner about the module cache (Global Constraints), then
`cd api && go get github.com/modelcontextprotocol/go-sdk@v1.8.0 && go mod tidy`.

**Files:**
- Create: `api/internal/app/mcp.go`, `api/internal/app/mcp_test.go`
- Modify: `api/go.mod`, `api/go.sum`

**Interfaces:**
- Consumes: `checkAndRecord` (Task 1), `*RateLimiter` (Task 3), `SentenceRepository`.
- Produces: `func newMCPHandler(srv *Server, ownerUID string, limiter *RateLimiter) http.Handler`. It
  returns `mcp.NewStreamableHTTPHandler(func(*http.Request) *mcp.Server { return newMCPServer(srv, ownerUID, limiter) }, &mcp.StreamableHTTPOptions{Stateless: true, JSONResponse: true, MaxRequestBodyBytes: 64 << 10})`.
- `newMCPServer` builds `mcp.NewServer(&mcp.Implementation{Name: "eagle", Version: "1.0.0"}, nil)` with
  the four tools below via `mcp.AddTool`. Each handler first calls `limiter.Take()`. When over the
  limit, it returns the error `Rate limit reached: try again in N seconds`, with N rounded up and at
  least 1. Handlers return `(nil, out, nil)` on success and `(nil, zero, errors.New(msg))` on a tool
  error. The SDK turns that into `isError: true`, and typed outputs become `structuredContent` plus
  JSON text. Wrap unexpected errors as `Internal error` after `log.Printf("mcp <tool>: %v", err)`.

**Tool definitions (exact; this is what Muse sees):**

1. `get_practice_sentence`
   - Description: `Get a random Japanese sentence for the owner to translate into English — the same pick as the eagle app (skips mastered and reported sentences). The English answer is not included: ask the owner for their translation, then call check_answer with this id.`
   - In: `Levels []int \`json:"levels,omitempty" jsonschema:"optional difficulty levels to pick from, each 1–5; omit for any level"\``
   - Out: `{id int, japanese string, level int, correct_count int, incorrect_count int}`. No `english`.
   - Annotations: `ReadOnlyHint: true`.
   - Errors: a level outside 1–5 → `levels must be between 1 and 5`. Dedupe like the REST handler.
     `ErrNoCandidate` → `No sentences left to practice at these levels`.
2. `check_answer`
   - Description: `Grade the owner's English translation of a sentence from get_practice_sentence and save it to their eagle history, exactly like answering in the app (wrong answers appear on the app's Mistakes page). Pass the owner's answer as they wrote it; don't correct it first.`
   - In: `SentenceID int \`json:"sentence_id" jsonschema:"the id from get_practice_sentence"\``,
     `Answer string \`json:"answer" jsonschema:"the owner's English translation, as written"\``.
   - Out: `{is_correct bool, your_answer string, correct_answer string, previous_wrong_answers []{answer string, at string}}`.
     `previous_wrong_answers` lists the latest 5, newest first, from before this attempt.
   - Annotations: `DestructiveHint: false`, `IdempotentHint: false`.
   - Errors:
     - `sentence_id` ≤ 0, or `ErrNotFound` → `Sentence <id> not found`. Nothing is recorded.
     - Blank after trim, or > `maxUserAnswerLength` bytes → `answer must be 1–2000 bytes`.
3. `list_mistakes`
   - Description: `List the owner's past wrong answers in eagle, most recently missed sentence first, each with the correct English and their latest wrong attempts. Use it to coach the owner on recurring mistakes. Page with limit and offset.`
   - In: `Limit int \`json:"limit,omitempty" jsonschema:"sentences per page, 1–50; default 10"\``,
     `Offset int \`json:"offset,omitempty" jsonschema:"sentences to skip; default 0"\``.
   - Out: `{total int, offset int, has_more bool, mistakes []{sentence_id int, japanese string, correct_answer string, wrong_answer_count int, latest_wrong_answers []{answer string, at string}}}`.
     `latest_wrong_answers` holds at most 3; `wrong_answer_count` is the full count.
   - Annotations: `ReadOnlyHint: true`.
   - Errors: `limit` outside 0–50 → `limit must be between 1 and 50` (0 means the default 10).
     `offset` < 0 → `offset must be 0 or more`. An offset past the end gives an empty list,
     `has_more: false`.
4. `report_sentence`
   - Description: `Report an eagle sentence as broken (wrong or unnatural Japanese or English) so it is no longer given for practice. The app has no undo, so confirm with the owner first.`
   - In: `SentenceID int \`json:"sentence_id" jsonschema:"the id of the sentence to report"\``.
   - Out: text only: `Reported sentence <id>; it won't be given for practice again.`
   - Annotations: `DestructiveHint: true`, `IdempotentHint: true`.
   - Errors: id ≤ 0, or `ErrNotFound` → `Sentence <id> not found`.

Helper: `callTool(t, name string, args map[string]any) *mcp.CallToolResult`.
