# Node 26 LTS (26.13.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every place in eagle that sets or assumes a Node version moves from 24.22.3 to 26.13.1 LTS, and CI, the frontend build and the e2e suite pass on it.

**Architecture:** Production has no Node runtime. The API is Go on Cloud Run (`api/Dockerfile` uses `golang` and `alpine` images), and Hosting serves the static `fe/out` export. Node is used only to build and test the frontend and to run the e2e suite. The change is therefore pins, ranges and `@types/node`, verified locally with a Node 26.13.1 toolchain kept inside the worktree, then in PR CI.

**Tech Stack:** Next.js 15.5.29 static export, vitest 4, Playwright 1.62, firebase-tools 15.22.0 (Hosting deploy and emulators), GitHub Actions `actions/setup-node`, Volta.

**Spec:** the task brief from 2026-11-23, and the survey `/tmp/node26-survey/REPORT.md` §0, §2.1 and §3. The brief named `/tmp/node26-survey/eagleRT.md`, which does not exist. `REPORT.md` is the only file in that directory and has the eagle section. Every survey finding used here was re-checked against this worktree (base `1e17963` = `origin/main`).

## Global Constraints

- Target Node: `26.13.1`, an exact pin as in the existing convention. Re-checked on nodejs.org/dist/index.json on 2026-11-23: it is the newest 26.x (2026-11-10, LTS "Lithium", `security: true`, npm 11.20.0). The next release is the 27 alpha.

- `engines.node` range: `>=26.13.1 <27`, the same shape as the current `>=24.22.3 <25`.
- `@types/node`: `^26` (latest 26.6.6).
- No code comments. Never disable lint or type rules.
- No secrets, emails or project IDs in new files, commits or the PR. Refer to "the eagle Firebase project" or "the Cloud Run service" instead.
- Don't change the Mac. No global npm installs, no Volta fetch or default change, nothing written under `~/.npm` or `~/Library/Caches/ms-playwright`. All Node 26 tooling lives in `<worktree>/.node26/`, which is never committed.
- Never merge. Never post GitHub comments. English for commits, the PR title and the PR description.

## Node 26 risks for what eagle uses

- **Removed/changed APIs** (`writeHeader`, `_stream_*`, `module.register` runtime deprecation, DEP0182 EOL, `--experimental-transform-types`): grep of `fe/src`, `fe/*.ts|mjs`, `e2e/**` finds none. Deep transitive use (Next build, vitest, Playwright, firebase-tools emulators) can only be ruled out by running them, which Tasks 1–2 do.
- **Undici 8 global fetch / Temporal global**: vitest runs `fe` tests under Node with jsdom; firebase-tools uses fetch. Covered by `npm test` and the e2e run.
- **ABI 147**: no Node-ABI native addon is in either lockfile (`@next/swc-*`, `lightningcss`, `@tailwindcss/oxide` and `sharp` are per-platform binaries). `npm ci` plus build proves it.
- **firebase-tools 15.22.0 on 26**: predates Node 26 support work upstream. The emulators (auth in Node; firestore in Java 21) are exercised by the e2e suite. Expect an `EBADENGINE` warning for `superstatic@10` on the firebase-tools install. It is a warning only (no `engine-strict` anywhere).
- **Volta in the worktree**: after the pins change, any `npm`/`node` call through a Volta shim in `fe/` or `e2e/` would make Volta fetch 26.13.1 into `~/.volta`, which is a Mac change. Every command below runs with `.node26/bin` first on `PATH`, and Task 0 asserts that.
- **Production**: the merge triggers `deploy-fe` (paths `fe/**`, `deploy-fe.yml`), so the live site is rebuilt with Node 26 and redeployed. `deploy-api` does not trigger (no `api/**` change).

## Review Focus

## Post-merge deploy verification (after the user merges)

Merging deploys to production. Only `Deploy Frontend` triggers. `Deploy API` doesn't, because no `api/**` changed.

1. The `Deploy Frontend` run for the merge commit is green. Its setup-node step shows `v26.13.1`, and lint, typecheck, test, build and the Hosting deploy all succeeded.
2. The live site serves the new build. The `buildId` in the served HTML (`/_next/static/<buildId>/`) changed from before the merge, and the Hosting release time matches the run.
3. Smoke test in the browser: the site loads, Google sign-in works, a practice sentence loads from the API, and there are no new console errors.
4. Trigger `Audit nightly` with `workflow_dispatch` (or wait for 18:10 UTC). The `fe-prod`, `fe-all` and `e2e-all` jobs run on 26.13.1 and are green, and the Go and image jobs are unaffected.
5. Rollback if 1–3 fail: revert the PR. The revert touches `fe/**`, so `deploy-fe` redeploys a Node 24 build. Hosting's previous release can also be restored from the Firebase console.

After merge, the user's first `npm` in `fe/` or `e2e/` on the Mac makes Volta fetch 26.13.1 into `~/.volta`. The Volta default (24.16.0) and global tools are not changed by this plan.
